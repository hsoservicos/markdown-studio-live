# Documentação — Markdown-Studio

Documentação em **Diataxis** (tutorial → how-to → explanation → reference), conforme padrão BMAD.

| Seção                                          | Para o que serve                                                          | Comece por                     |
| ---------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------ |
| **[Tutorials](tutorials/getting-started.md)**  | Aprenda o fluxo passo a passo (primeira execução, primeiros recursos)     | `tutorials/getting-started.md` |
| **[How-to](how-to/re-edit-overview.md)**       | Resolver tarefas concretas (planejar mudança, adicionar função, publicar) | `how-to/re-edit-overview.md`   |
| **[Explanation](explanation/architecture.md)** | Entender o sistema: o fluxo de renderização, contratos e decisões         | `explanation/architecture.md`  |
| **[Reference](reference/api-convert.md)**      | Consulta precisa de APIs, chaves de storage e scripts                     | `reference/api-convert.md`     |
| **Snapshot v1.1.0**                            | Registro compacto do estado estável desta release                         | `reference/snapshot-v1.1.0.md` |

## Convenções de escrita

- pt-BR (padrão do projeto).
- Estilo claro: frases curtas, verbos no imperativo em how-to.
- Código sempre com caminho de arquivo exato (ex.: `docs/tutorials/getting-started.md`).
- Cada tópico novo de domínio entra no **Glossário** do PRD (`specs/prd.md`) antes de ser usado.

Esboços conceituais ficam em `docs/diagrams/` (Excalidraw ou Markdown de texto).
